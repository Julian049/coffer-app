## How work is done here

- Work proceeds **sprint by sprint** following `sprint-plan.md`; only implement the current sprint's stories (no scope creep). Each story = one issue, one branch `feature/<issue>-<slug>` from `develop`, one PR to `develop`, with a "Cómo probar" section for manual testing by the product owner (@Julian).
- Never push to `main` or `develop` directly, never force-push shared branches, never commit secrets (keystores, `.env`, keys). Release signing uses GitHub secrets `RELEASE_KEYSTORE_BASE64`, `RELEASE_KEYSTORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`.
- **Do not change the `applicationId`** (`com.dev.julian09.financeapp`): changing it would make Android treat the app as a different one and the MVP local database could not be migrated. Only the visible app name becomes "Coffer".
- Ask the product owner when the SRS, design or prototype are ambiguous; structural decisions get an ADR.
- Conventional Commits; CHANGELOG (Keep a Changelog) updated in every PR under `[Unreleased]`. Commits produced with AI assistance carry a `Co-Authored-By` trailer.

## Project

Single-module Android app (`:app`, package and `applicationId` `com.dev.julian09.financeapp`; **never change the `applicationId`**). Kotlin + Jetpack Compose + Material 3 + Navigation Compose + Hilt (KSP) + Room + Retrofit 3/OkHttp 4 with **kotlinx.serialization** (no Gson). minSdk 31, targetSdk 36, compileSdk 37 (current AndroidX and OkHttp 5 require it), no desugaring. AGP 9 with built-in Kotlin (no `kotlin-android` plugin). README, UI strings, log messages and test names are in Spanish; CHANGELOG follows Keep a Changelog in English. Commits use Conventional Commits.

Version: `versionName` = SemVer, `versionCode` = `MAJOR×10000 + MINOR×100 + PATCH` (`0.2.0` → 200), both in `app/build.gradle.kts`.

## Commands

On this machine the Android SDK is installed on Windows, so from WSL run Gradle through Windows: `cmd.exe /c "gradlew.bat <tasks>"` (it also avoids WSL's DNS hiccups). If the Kotlin daemon crashes for lack of memory, add `-Pkotlin.compiler.execution.strategy=in-process`.

```bash
./gradlew assembleDebug assembleStaging         # APKs
./gradlew installStaging                        # install on a connected device
./gradlew testDebugUnitTest                     # JVM tests (JUnit 4, MockK, Konsist, Robolectric)
./gradlew recordRoborazziDebug                  # re-record reference screenshots after an intended visual change
./gradlew ktlintCheck                           # style (ktlintFormat fixes most issues)
./gradlew createDebugUnitTestCoverageReport     # JaCoCo coverage of the unit tests (AGP built-in)
./gradlew lint
./gradlew lint ktlintCheck testDebugUnitTest assembleStaging -Proborazzi.test.verify=true   # what CI runs
```

Network tests use MockWebServer (`mockwebserver3`) with the same interceptor/authenticator wiring (`TestNetwork`) and `FakeSessionStore`. Instrumented tests (`src/androidTest`, e.g. `SessionStoreTest` with the real Keystore) are **run by hand** (`./gradlew connectedDebugAndroidTest` on a device or an emulator with API 31–36), not in CI. On this machine, if Gradle fails with "paging file is too small", add `--max-workers=1`.

Robolectric runs with a plain `android.app.Application` (`src/test/resources/robolectric.properties`) because `FinanceApp` would open the SQLCipher database, whose native library only exists on devices; JVM database tests use `inMemoryDatabase()` (same schema, no SQLCipher) or `LedgerFixture` (real repositories over it, rows already SYNCED) and encryption is covered by `EncryptionInstrumentedTest`.

Unit tests run with `isReturnDefaultValues = true`, so `android.util.Log` calls are no-ops in JVM tests.

CI (`.github/workflows/ci.yml`) runs on every PR; `instrumented.yml` runs the instrumented tests on an API 31 emulator (on release, on PRs that touch them, or by hand); and push to `develop`/`main` and uploads the staging APK as the `coffer-staging-apk` artifact (that is what the PO installs to test a PR). `release.yml` runs on `v*` tags: signed `assembleRelease bundleRelease` and a GitHub Release with APK, AAB and `SHA256SUMS.txt`. Dependabot updates Gradle and Actions weekly.

## Architecture

Target structure: detailed-design §6.2.2. Today:

The Material `ColorScheme` is derived from the tokens with every surface slot flat (no tonal tint). No dynamic color. Do not hardcode colors in screens.

`CardDetailSections` inside Detalle de cuenta; `PayCardSheet` + `PayCardViewModel`: Hoja · Pagar tarjeta, shared by Home, the card detail and Gastos recurrentes; `CardFormat.kt` parses and shows rates), `recurring` (`RecurringViewModel` for Gastos recurrentes, also listing card statements, `RecurringFormViewModel` for new and edit by the route's `id`, `PendingSheets` + `PendingViewModel`: Hoja · Pendiente, Hoja · Pagar pendiente and the finalize confirmation, shared by Home and the list; Each screen has a stateless `*Content` composable used by tests and screenshots.
- **Domain**: `finance/BalanceCalculator` (balances, available total, monthly change), `finance/FoxRules` (mascot mood; order approved by the PO on 2026-10-17; ATTENTIVE when a payment is due in ≤ 2 days or overdue), `finance/RecurrenceCalculator` (dates are the start plus k steps, so the 31st survives short months; a start in the past or a new schedule begins at the first date from today), `ObserveRecurringOverview`, `ObservePendingPayments`, `PayPending`, `SkipPending`, `EndRecurrence`, `SendReminders` (recurring expenses and card statements; a card's last notice lives in `sync_meta` as `card_notified:<id>`), `UpdateReminderSettings`, `CreateCard`, `UpdateCard`, `ObserveCards` (`CardOverview`: debt, statement, live deferred purchases), `ObserveCardDues`, `DeferCardPurchase`, `PayCreditCard`, `PreviewImport`, `CommitImport`, `RunImport` (resolutions, duplicates, batches of 500 through `TransactionRepository.insertAll`), `ExportCsv` (native columns `NATIVE_COLUMNS`); they return a `LedgerError` (shown with `LedgerError.message()`) or null and call `SyncScheduler.requestSync()` after writing. `model/Money` (Long ×10⁴, ADR-0004, with `+`, `-`, comparison), `model/SyncStatus`, `model/Session` (`SessionState` Loading/SignedOut/Active/Expired, `UserProfile`), `model/AuthFailure` (what auth screens show) and `AuthValidation` (same rules as the contract, checked before any network call), `port/Clock`, `port/ReminderNotifier`, `port/ReminderScheduler`, `port/ServerStatusRepository`, `port/AuthRepository`, use cases `CheckServerStatus`, `RegisterUser`, `Login`, `LoginWithGoogle`, `Logout`, `ObserveSession`.
- **Session** (`data/session`, SEQ-01/03): `SessionStore` interface, implemented by `EncryptedSessionStore` (typed DataStore `session.bin`, bytes AES-256-GCM encrypted with the Keystore key `coffer_session_key` via `KeystoreCipher`; an undecryptable file resets to signed out). `DeviceIdProvider` keeps a per-installation UUID in SharedPreferences (survives logout). `AuthInterceptor` adds the bearer token except on `AuthApi.PUBLIC_PATHS`; `TokenAuthenticator` refreshes once under a lock on 401 (`AuthApi.refresh` is a blocking `Call` because it runs inside OkHttp) and retries, marks the session expired when the refresh is rejected, and does nothing on network errors. Both read the store with `runBlocking` on OkHttp's threads. `AuthRepositoryImpl` maps RFC 9457 problems to `AuthFailure` (409 tells username from email by the server's wording).
- **Data**: `clock/SystemClock`, `remote/HealthApi` (sends `Accept: application/json` because Actuator otherwise answers with its own vnd media type), `repository/ServerStatusRepositoryImpl`.
- **DI**: `NetworkModule` (`Json { ignoreUnknownKeys }`, OkHttp with 60 s timeouts because Render's free plan sleeps, Retrofit on `BuildConfig.API_BASE_URL`), `DispatchersModule` (`@IoDispatcher`, `@DefaultDispatcher`), `RepositoryModule` (binds ports).
- **Local database** (`data/local`, data-model §5): `FinanceDatabase` (`finance.db`, Room version 4: 1 → 2, 2 → 3 and 3 → 4 are `AutoMigration`s adding `change_log`, `recurring_expenses` and the card tables (`credit_card_details`, `deferred_purchases`, `installments`), checked by `FinanceDatabaseMigrationTest` with the exported schemas in `app/schemas/`, which are also debug assets; commit them; never a destructive fallback) opened with SQLCipher (`SupportOpenHelperFactory`) using `DatabaseKeyProvider` (random 256-bit passphrase wrapped with the Keystore key `coffer_database_key`, file in `noBackupFilesDir`; if it cannot be unwrapped the database is deleted and rebuilt from the cloud). Entities mirror the server tables without `user_id`/`version`, plus `syncState` (`PENDING`/`SYNCED`/`FAILED`, the outbox) and `syncError`; amounts are `Long` ×10⁴, instants epoch ms, UUIDs and dates text. `sync_meta` holds `pull_cursor`, `last_sync_at`, `legacy_migrated`. `LegacyDatabaseMigrator` runs once at app start (`FinanceApp`, on `@ApplicationScope`): reads the MVP `finance_db` with plain SQLite, writes it with the V6 rules and the server's fixed UUIDs (account `…a1`, categories `…b1`/`…b2`), all rows `PENDING`, then deletes `finance_db`. Ports `AccountRepository`, `CategoryRepository`, `TagRepository`, `TransactionRepository`, `RecurringRepository` (`pay` writes the expense, its history and the next date in one transaction), `CardRepository` (`insertDeferred` and `pay` write the movement, its history and the plan or the settled installments in one transaction; deleting a purchase deletes its plan), `SettingsRepository` (defaults until the first sync seeds the row) → `*RepositoryImpl` (transaction writes log CREATE/UPDATE/DELETE through `ChangeLogWriter` in the same transaction; search is one SQL shape, `SEARCH_FROM`, for rows and totals): balances come from `AccountDao.observeBalances(before)` (sums per account, detailed-design §6.6.3) and every write runs in `withTransaction`, stamps `updatedAt` with the `Clock` and leaves the rows `PENDING`. Icon keys for accounts and categories live in `ui/components/LedgerIcons.kt`.
- **Sync** (`data/sync`, ADR-0006, SEQ-02/08/09): `SyncEngine.sync()` = push the outbox (rows with `syncState = PENDING`, in `SyncTables.all` dependency order, batches of 200; `APPLIED`/`STALE` → `SYNCED` and `REJECTED` → `FAILED` only if `updatedAt` did not change while sending) → pull from `sync_meta.pull_cursor` (pages of 500; `ChangeApplier` keeps a local unsent edit that is as new or newer, otherwise writes the server row as `SYNCED`, and saves the cursor in the same transaction) → on the first round, `BaseCatalogSeeder` and `initial_sync_done`. `sync_meta.owner_user_id` pins the database to its first account: another account's session throws `ForeignDataException` and never syncs. `SyncWorker` (`@HiltWorker`; `FinanceApp` provides the `HiltWorkerFactory`, the default WorkManager initializer is removed in the manifest) maps errors: network, 5xx, 429 → retry with backoff, anything else → failure. `SyncScheduler` (`SyncSchedulerImpl`): `requestSync` (unique, KEEP, 5 s, needs network), `requestInitialSync` (expedited, returns the work id), `ensurePeriodic` (15 min), `cancelAll` (called by `Logout`), `observeStatus` (unsynced rows, running work, `ConnectivityObserver`, `last_sync_at` → `SyncStatus`), `observeInitialSyncDone`, `observeInitialSync(id)` (received, total and per entity from the worker's progress data). `SyncEngine` runs one round at a time (process-wide `Mutex`). `change_log` syncs last (`changeLog`) and is left out of the pending badge count. To sync a new table: entity + DAO sync queries (`pending`, `syncInfo`, `markSynced`, `markFailed`) + a `SyncTable` in `SyncTables.all`.
- **Import** (`data/io`, `data/importing`, SEQ-13): `CsvReader` (RFC 4180 in streaming, `,` or `;`, UTF-8 or Windows-1252) and `CsvWriter`; `ContentCsvFiles` (port `CsvFiles`, through the ContentResolver); `ImportSchedulerImpl` saves the plan in `sync_meta` (`import_plan`) and enqueues the unique work `import` → `ImportWorker` → `RunImport`, which leaves the summary in `sync_meta` (`last_import`).
- **Reminders** (`data/reminder`, SEQ-10 §10.3): `ReminderSchedulerImpl` (unique daily periodic work `reminders`, first run near 08:00, no network; scheduled with the sync on every start, cancelled by `Logout`), `ReminderWorker` → `SendReminders`, `NotificationPublisher` (channel `pending_payments`, "Pagos pendientes"; checks `POST_NOTIFICATIONS`).
- `KeystoreCipher` takes an alias: `SESSION_KEY` for tokens, `DATABASE_KEY` for the database passphrase (ADR-0008: one key per purpose). Android backup and device transfer are off (`allowBackup=false`, `data_extraction_rules.xml` excludes everything).

Rules in `ArchitectureTest` (Konsist, runs with the unit tests): `domain` imports no `android.*`, `androidx.*` or `data`; no `Double`/`Float` properties, parameters or return types in `domain` (ADR-0004); `ui` does not import `data`.
